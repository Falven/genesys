# Genesys local integration coverage catalogue

This catalogue supports the [published specification](spec.md). It preserves 51 coverage groups, each with a named Genesys defect. Groups are not a required test count or SDK/OS cross-product. Each concrete case must use the smallest fixture and variants that expose its stated defect. [Coverage dependencies](coverage.md) links groups to product implementation tickets. All runtime coverage remains unexecuted by this planning work.

## Coverage groups

Each row names a Genesys defect and observable acceptance behavior. IDs are planning references, not new product APIs. Add SDK variants only for distinct Genesys analysis, emission, build, packaging, or launch paths. Do not multiply tests by Temporal primitive or language pair alone. Any concrete case split from a row must retain its own defect statement. Runtime rows must execute actual Genesys-produced artifacts or Genesys-managed processes against real Temporal; a manually assembled native application alone is insufficient.

| D04 | Use aliases, inheritance, re-exports, native overrides, dynamic identities, and file moves. | Native identities and visibility survive; unresolved names remain unresolved; moving a file does not rename a definition. | Identity contract | Analysis/emission changes a native identity, loses an alias/visibility rule, or invents a resolved name. |
| D05 | Reuse one name in independent Workers, then collide within one native scope. | Independent scopes remain valid; conflicts name relevant sources and respect native override rules. | Registration scope | Conflict analysis merges independent scopes or misses a known same-scope collision. |
| D06 | Use unsupported static forms, invalid native definitions, and unavailable SDK features. | Diagnostics distinguish all three; explicit native assembly remains available for valid unresolved code. | Native preservation | Genesys mislabels a tooling limit as an SDK limit, emits invalid registration, or blocks valid explicit assembly. |
| D07 | Use unambiguous, ambiguous, and unavailable Worker entrypoints. | Native package conventions select valid programs; ambiguity lists candidates and does not guess. | Worker entrypoints | Entrypoint analysis chooses the wrong executable or guesses when native package evidence is ambiguous. |

| R08 | Package and launch an authored Worker with a distinctive native converter/interceptor and explicit Worker options through Genesys. | Real execution proves the packaged modules and authored settings are used. | B01 | Build a valid project, then fail analysis, generation, native compilation, or publication preparation; also publish concurrent candidates. | Only successful complete builds become current; each selected manifest is complete; failed candidates leave the previous selector and authored files intact. | B05 | Inspect immutable manifests, metadata, generated files outside `.gsys`, and removed native outputs. | All required outputs and provenance are recorded; read the current selector once and follow immutable paths. | C01 | Start `gsys dev` in interactive and noninteractive environments with no selectors. | Managed Temporal and all discovered Worker programs start without a prompt; errors and plain logs are visible. | CLI contract | Supervision omits or duplicates Worker launches, prompts without a TTY, omits managed Temporal, or loses process logs. |

| C07 | Launch one native program containing multiple Worker instances. | Known instances and task types receive separate attributed observations; incomplete coverage is reported. | Worker program cardinality | Supervision attributes evidence to the wrong Worker instance or claims complete coverage from a subset. |

## SDK fixture variants

These variants come from checked-in SDK implementation docs, not from an assumption that the SDKs share one API.

| SDK | Distinct fixture forms |
| --- | --- |
| Go | Free functions and receiver methods; aliases; package-local visibility; separate receiver scopes; native name/prefix overrides; preconstructed Nexus service/factory values; native `main` package. |
| Java | Annotated interfaces and implementations; inherited Activity methods; application-owned implementation objects; native package/class visibility; Maven/Gradle package context; ambiguous entrypoints. |
| .NET | Partial/nested types, inherited/nonpublic Activity methods, native name constants and dynamic definitions; direct instance registration and native Hosting DI; unresolved MSBuild/project forms remain explicit limitations. |
| PHP | Workflow/Activity attributes and interfaces; prefixes; factory callback construction; RoadRunner host plus PHP children; no fabricated Nexus service registration for the reviewed SDK. |
| Python | Decorated classes/functions, bound methods, aliases/re-exports, existing instances, dynamic catch-all versus unresolved computed name; package layouts, native environment and entrypoints. |
| Ruby | Definition subclasses, aliases and native definition objects; application instances/factories; class visibility and conditional declarations; Gemfile and bin/exe launch forms. |
| Rust | Multiple native macro definitions; private module-local includes; shared Activity implementer; factory-only Workflow; Cargo module/target/features; SDK capability diagnosis for absent service-handler registration. |
| TypeScript | ESM/CJS and `.mts` layouts; callable exports/re-exports/default fallback; Activity objects/bound functions/native overrides; Nexus service objects; sandbox imports; emitting native build versus unresolved startup. |
