## Genesys constraints on these transfers

Q2 is removed. Tests run locally, and OS variants are restricted to distinct Genesys packaging, path, native launch, and shutdown risks. Q3 requires real failure reproduction first; simulation needs a named Genesys defect and a recorded reason the real setup is impractical. No separate fault-simulation harness is planned. Q4 activates tests with their implementation and never counts skips as verified support.

Q1 is settled: every transfer must name a defect in Genesys discovery, generated registration, builds, packaging, or supervision. Native primitives only provide observable probes. The scenario descriptions above are Reference evidence; they do not authorize a Temporal durability, replay, cancellation, or serialization conformance suite. Real Temporal execution must exercise the Genesys-produced artifact or owned process lifecycle.

The adjacent scenario list is reference evidence, not a Genesys feature list. Do not port `reference init`, live models, chat streams, approval APIs, agent extensions, Vercel adapters, or a one-second shutdown deadline. Genesys has no init command requirement. Native Workflow Signals/Updates can model a durable wait without introducing an approval framework. Genesys must honor native graceful shutdown without another fixed deadline. Runner cleanup after a timed-out test is a separate harness operation. Genesys builds are intentionally retained at their final absolute path; do not import Reference's relocation guarantee. Packed CLI resource resolution is still applicable. Compose is explicitly in Genesys scope.

## Follow-up: canonical eval IDs and counting arrays

Runtime source is `packages/reference/src/evals/runner/discover.ts:63–77,90–117`:

- A single definition gets file path relative to `evals/`, slash-normalized, minus `.eval.ts`: `evals/sub/weather.eval.ts` becomes `sub/weather`.
- An array export gets one ID per entry with four-digit, zero-based index: `sub/weather/0000`, `sub/weather/0001`, etc. Description text is not used to derive ID. Array reordering changes which case owns a numeric ID.
- Exact-or-prefix filtering (:79–87) means requesting file ID selects all of its array entries. Duplicate derived runtime IDs fail (:147–155).
- CI script `.github/scripts/discover-e2e-fixtures.mjs:256–274` scans only file IDs without importing definitions; it cannot count array entries. Its tag check (:251–253) is a file-source regex, not per-array-element evaluation. Therefore distinguish file count, imported executable case count, and CI matrix-leg count. Mixed-tag arrays would be conservatively recognized as real-model files by discovery while actual runner filtering applies definition tags.

Sent ID semantics and evidence directly to the `reference_cases` audit lane.
